# 京东 16.0 文案规范

使用此技能处理京东中文文案。文案必须遵循 2026 版京东 App 16.0 语气：**简单、可靠、亲切**。优先从用户视角表达用户目标、用户利益和下一步动作；营销表达要直接、可信、克制，可转化但不夸大。

## 任务路由

先判断任务类型，再按需读取 reference。不要默认加载全部规则。

| 任务类型 | 适用场景 | 必读规则 |
|---|---|---|
| UX 交互文案 | Toast、弹窗、按钮、空状态、报错、升级提示、客服售后、入口命名、功能命名 | `references/copy-rules.md` |
| 品牌营销文案 | 品牌主张、活动营销、频道导流、运营话术、权益表达、服务承诺、情绪陪伴、商品种草 | `references/brand-marketing-rules.md` |
| 电商高风险文案 | 商品卖点、主图/商详、价格优惠、活动承诺、功效/功能、资质认证、排名销量、保健/食品/器材等类目 | `references/commerce-compliance-gates.md` |
| 输出组织 | 需要生成候选、评审改写、视觉运营位执行稿、风险自检 | `references/output-templates.md` |

如果一个任务同时涉及多个类型，按风险优先级处理：电商高风险文案 > 品牌营销文案 > UX 交互文案。涉及商品、价格、服务承诺或类目红线时，必须先过电商门禁，再写文案。

## 必要输入

收集或从上下文推断以下信息；缺失时标注“缺失”，不要编造：

- 触点位置：页面、卡片、弹窗、Push、会场、频道、商详、主图、客服等。
- 版位角色：头图定调、楼层导流、商品转化、权益解释、任务提醒、结果反馈等。
- 用户状态：新用户、会员、已下单、浏览中、支付中、售后中、负面情绪等。
- 业务目标：理解、点击、领取、下单、留存、信任、安抚、命名识别等。
- 下一步动作：查看、领取、购买、刷新、重试、预约、咨询、返回等。
- 限制条件：字数、必须保留术语、价格/权益规则、活动时效、法务或平台要求。
- 证据材料：数据来源、资质文件、检测报告、批准文号、认证编号、活动规则、服务规则。

## 工作流程

1. 判断任务类型、触点和版位角色；同一主题在不同触点必须采用不同写法。
2. 按路由读取必要 reference。
3. 先定义触点任务：头图负责主题和进入理由，楼层负责分类导流，商品卡负责具体卖点，Push 负责即时动作。
4. 提炼用户利益：把功能、权益、参数、活动规则翻译成“用户能得到什么”。
5. 核查证据边界：数据、价格、排名、功效、认证、服务承诺必须有来源。
6. 生成或改写文案：优先简单直白、用户视角、信息前置、术语一致。
7. 输出 3-5 条候选；候选之间必须是不同策略方向，不要只替换同义词。
8. 做风险自检：可信、清晰、合规、转化、可落地。

## 写作原则

- 简单：使用大众能理解的词汇和短句，删除无用修饰、行业黑话和内部术语。
- 可靠：陈述可验证事实，提供确定性引导，不编造数据、承诺、资质或效果。
- 亲切：用对话式表达替代命令式表达，保持克制的温度，不甜腻、不油腻。
- 用户视角：优先写用户能做什么、能得到什么，再写平台动作。
- 一处一意：一个标题、按钮或运营位只传达一个核心利益点。
- 可落地：文案要能放进目标界面、运营位或设计稿；图内文案必须短、清楚、有层级。
- 触点分工：不要把会场头图写成商品卡、把楼层标题写成品牌口号、把 Push 写成会场主题。

## 高风险停顿

遇到以下情况，先输出风险判断和安全替代方向，不直接生成上线文案：

- 用户要求写无证据的“最低价、第一、销量领先、100%、全网最、必达、必赔”等表达。
- 普通食品、保健食品、运动器材、母婴、美妆、医疗器械、药品、金融保险等敏感类目缺少资质边界。
- 商品文案涉及改善、治疗、修复、调理、增强、控糖、减脂、抗衰、矫正、康复等效果暗示。
- 活动、权益、服务承诺缺少真实规则、限制条件或适用范围。

```text
3. ...

```
